# sHome for Home Assistant

[![hacs_badge](https://img.shields.io/badge/HACS-Custom-41BDF5.svg)](https://github.com/hacs/integration)


삼성SDS/직방 **IHP(sHome)** 월패드용 Home Assistant 커스텀 통합.
클라우드 REST API(`shome-api.samsung-ihp.com`)를 그대로 사용해, 로컬 배선을 건드리지 않고 계정 자격증명만으로 아파트 월패드 기기·데이터를 연동한다.

## 지원 기능

| 도메인 | sHome 기기 | 기능 |
|--------|-----------|------|
| `light` | 조명(jm), 디밍(dm), 감성조명(sjm) | 켜기/끄기, 디밍 밝기, 감성조명 모드 |
| `climate` | 난방(bl/br), 냉방(aircon) | 전원, 현재/희망 온도 |
| `fan` | 환기(vf) | 켜기/끄기, 풍량 |
| `cover` | 커튼(ct) | 열기/닫기/정지 |
| `valve` | 가스밸브(gv) | 닫기(안전상 원격 열기 불가) |
| `switch` | 퇴실스위치(os) | 일괄소등 |
| `select` | 홈모드 | 외출/재실/방범 등 전환 |
| `sensor` | 에너지 | 전기/수도/가스/온수/난방 사용량 |
| `sensor` | 관리비 | 이번 달 관리비 합계·항목별 (관리비 제공 단지에서만) |
| `sensor`* | 실내환경(환경센서) | 온도/습도/CO2/미세먼지 (레거시 세대, 실험적) |
| `switch`* | 스마트콘센트(대기전력) | 콘센트 on/off (레거시 세대, 실험적) |

### 세대 유형에 따른 지원 범위

로그인 시 `isMhpsUser`로 세대가 갈린다.

- **MHPS 세대** (`isMhpsUser=1`, 신형): 위 표의 `*` 없는 항목 전부 — **구현·라이브 검증 완료.**
  이 세대의 sHome 클라우드 API에는 실내환경/스마트콘센트 등이 노출되지 않는다(월패드 로컬에만 존재).
- **레거시 세대** (`isMhpsUser=0`, 구형): `/v16·/v18/settings/*` 계열 사용. `*` 표시 항목(실내환경 센서, 스마트콘센트)을
  **실험적으로 구현**했으나, 개발용 계정이 MHPS라 **라이브 검증 불가** — 해당 세대 사용자의 테스트·피드백이 필요하다.
  시스템에어컨·보안센서·레거시 조명/난방 제어는 아직 미구현.

## 설치 (HACS 커스텀 저장소)

1. HACS → 통합(Integrations) → 우측 상단 ⋮ → **Custom repositories**.
2. 저장소 `https://github.com/ripe-avocado/shome_ha`, 카테고리 **Integration** 추가.
3. 목록에서 **sHome** 설치 후 Home Assistant 재시작.
4. **설정 → 기기 및 서비스 → 통합 추가 → "sHome"** 에서 아이디/비밀번호 입력.

또는 아래처럼 수동 설치:

### 수동 설치

1. 이 저장소의 `custom_components/shome/` 폴더를 HA 설정 디렉터리의 `config/custom_components/shome/` 로 복사.
2. Home Assistant 재시작.
3. **설정 → 기기 및 서비스 → 통합 추가 → "sHome"** 검색.
4. sHome **아이디**(전화번호 등)와 **비밀번호** 입력.
   - 비밀번호는 SHA-512로 해시되어 전송되며, HA는 평문을 config entry에 저장한다.
   - 로그인 시 임의의 16자리 기기ID(`mobileDeviceIdno`)를 1회 생성해 고정 사용한다.


## 실시간/폴링 동작

- MHPS 세대는 **공식 앱조차 기기 상태를 실시간 스트리밍하지 않는다** (앱은 화면 진입·제어 직후에만 갱신, 실시간 push는 방문자/경보 알림용 FCM뿐).
- 따라서 본 통합은 **클라우드 폴링**(기본 15초, 설정에서 15~600초 조정)이다.
- **HA에서 직접 제어**하면 명령값을 즉시 UI에 반영한다(optimistic). 폴링 지연은 **월패드/앱에서 직접 조작한 외부 변화**에만 영향을 준다.
- **제어의 물리 지연**: 실제 기기 반영은 `클라우드 → 월패드 → 기기` 릴레이라 1~3초 걸린다. 이는 **공식 앱과 동일한 구조적 지연**으로 통합에서 줄일 수 없다.
- **적응형 폴링**: 제어 직후 약 3초 간격으로 몇 차례 빠르게 재조회한 뒤 평상 주기로 복귀한다(연쇄/외부 변화를 신속히 반영).
- **명령 확인·재전송(confirm & retry)**: 제어 후 ~4초 뒤 실제 기기 상태를 다시 읽어 목표에 도달 못 했으면 자동 재전송(최대 2회). 클라우드→월패드→기기 릴레이 중 명령이 가끔 유실돼 조명이 안 꺼지던 문제를 완화한다.
- **명령값 고정(optimistic hold)**: 제어 후 명령값을 폴링이 확인해줄 때까지(최대 6초) 고정해, 전환 중 폴링값이 상태를 되돌려 깜빡이는 것을 막는다.
- **빠른 연타 주의**: ON/OFF를 1초 안에 연타하면 월패드가 명령 순서를 꼬아 **실제 상태 ≠ 마지막 명령**이 될 수 있다(월패드 특성). 이 경우 HA는 최대 6초 내에 실제 상태로 정정한다. 조작 사이 1~2초 간격을 두면 안전하다.
- 폴링 주기 변경: 통합 → 설정(옵션) → 폴링 주기(초).
- **부하 참고**: 1회 폴링은 세대 기기 수에 따라 수 개~십수 개의 API 요청이다(존재하는 타입만 조회, 에너지/관리비는 30분 캐시).
  기본 15초이며 최소 15초로 제한된다(하한). 이 주기는 **월패드/앱에서 직접 조작한 외부 변화를 HA가 반영하는 속도**를 결정한다(HA에서의 제어는 즉시 반응). 더 낮추고 싶어도 15초 미만은 막혀 있는데, 공개 배포 특성상 다수가 과도하게 짧은 주기를 쓰면 직방 서버가 rate-limit/차단해 **서비스 전체 접근이 막힐 수 있기 때문**이다. 부하가 걱정되면 30~60초로 올려도 된다.

## 주의사항

- **로그인 잠금**: 비밀번호를 5회 틀리면 계정이 ~10분 잠기고, 잠긴 동안 로그인을 재시도하면 타이머가 리셋된다.
  통합은 잠금 감지 시 자동 재시도를 멈추고 백오프한다. 앱에 잘못된 비밀번호가 저장돼 자동 재시도 중이면
  앱을 강제종료하고 올바른 비밀번호로 1회 로그인해 잠금을 해제한 뒤 통합을 설정하라.
- **가스밸브**: 안전상 원격 열기는 지원하지 않으며 닫기만 가능하다.
- 본 통합은 개인의 자택 계정 연동용 비공식 프로젝트다.

## 검증 상태 (2026-08-28)

MHPS 세대에서 로그인 · 기기 상태 조회 · 홈모드 · 에너지(전기/수도/가스/온수/난방) 라이브 검증 완료.
제어(쓰기) 및 레거시 세대(실내환경/콘센트)는 개별 검증 권장.
